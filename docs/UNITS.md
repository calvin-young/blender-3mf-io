# Units: what a Blender unit becomes in a 3MF file

3MF files written by this add-on are always in millimetres. By default, a scene with Unit Scale 1 (Blender's
default scene, or Unit System None) has **1 Blender unit = 1 mm**, whatever length unit Blender displays: the way
3D printing programs read unitless numbers, and the way Blender's own STL and OBJ exporters write them. A scene
whose Unit Scale was changed means it: 0.001 is millimetres, 0.01 centimetres, and so on (with Unit System None,
Unit Scale counts millimetres).

## Measured behaviour (2.7.7-fork.18)

Generated by `tests/integration/test_unit_matrix.py` (set `THREEMF_UNIT_TABLE` to a file path to regenerate it).
Import reads a 20 mm cube at x = 100 mm from a file in each unit; export writes a 20 unit cube. "u" is Blender
units, as `dimensions` shows them, and "scale" is the imported object's scale. The test fails if any case loses
the real size, if a build item gets a scale, or if import scales an object when one unit is the file's unit.

| Scene units | Means | Import 20 mm cube from a mm file | from an inch file | from a metre file | Export 20 unit cube |
|---|---|---|---|---|---|
| None, scale 1 | 1 unit = 1 mm | 20 u, scale 1 | 20 u, scale 25.4 | 20 u, scale 1000 | 20 mm |
| Metric, m, scale 1 (Blender's default) | 1 unit = 1 mm | 20 u, scale 1 | 20 u, scale 25.4 | 20 u, scale 1000 | 20 mm |
| Metric, mm, scale 1 | 1 unit = 1 mm | 20 u, scale 1 | 20 u, scale 25.4 | 20 u, scale 1000 | 20 mm |
| Imperial, in, scale 1 | 1 unit = 1 mm | 20 u, scale 1 | 20 u, scale 25.4 | 20 u, scale 1000 | 20 mm |
| Metric, mm, scale 0.001 | 1 unit = 1 mm | 20 u, scale 1 | 20 u, scale 25.4 | 20 u, scale 1000 | 20 mm |
| Metric, cm, scale 0.01 | 1 unit = 10 mm | 2 u, scale 0.1 | 2 u, scale 2.54 | 2 u, scale 100 | 200 mm |
| None, scale 1, preference off | 1 unit = 1000 mm | 0.02 u, scale 0.001 | 0.02 u, scale 0.0254 | 0.02 u, scale 1 | 20000 mm |
| Metric, m, scale 1, preference off | 1 unit = 1000 mm | 0.02 u, scale 0.001 | 0.02 u, scale 0.0254 | 0.02 u, scale 1 | 20000 mm |
| Metric, mm, scale 0.001, preference off | 1 unit = 1 mm | 20 u, scale 1 | 20 u, scale 25.4 | 20 u, scale 1000 | 20 mm |

With the preference **Unit Scale 1 Means Millimeters** off, every scene follows Blender's unit settings (1 unit =
Unit Scale metres), as upstream does. The fork did too up to 2.7.7-fork.15; 2.7.7-fork.16 and 17 treated only Unit
System None as millimetres.

## Notes

- **Why Unit Scale 1 means millimetres.** Unitless mesh formats (STL, OBJ, PLY) carry Blender's numbers as they
  are, and slicers and build preparation programs read them as millimetres, so 1 unit = 1 mm is the common
  convention for 3D printing. Blender's STL exporter writes 1 unit as 1 in the file unless its Scene Unit option
  is on, so a default scene exported to STL and to 3MF now gives the same size. The preference **Unit Scale 1
  Means Millimeters** (Export and Import tabs, on by default) turns this off.
- **To work in metres** (or any other unit) with this add-on, set Unit Scale to match: 1 m needs the preference
  off, since Unit Scale 1 is read as millimetres.
- **Where scale goes.** On export the unit factor goes into the vertices, so build-item transforms are only
  rotation and translation. On import it goes on each object's scale. Exporting objects that an import scaled
  0.001 keeps the right size, but writes that 0.001 into every build item, with vertices ×1000.
- **Size readouts.** The export dialog shows the size in the file; the import dialog shows the size of the
  selected file (files whose model is up to 50 MB) and the scale its objects will get in this scene. Both flag a
  build under 1 mm or over 1 m, and import warns afterwards if what it brought in is.
