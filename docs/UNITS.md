# Units: what a Blender unit becomes in a 3MF file

3MF files written by this add-on are always in millimetres. What one Blender unit means depends on the scene's
unit settings (Scene Properties, Units): Unit Scale is the number of metres per unit, and the length unit only
changes what Blender displays. The one exception is Unit System None, below.

## Measured behaviour (2.7.7-fork.17)

Generated by `tests/integration/test_unit_matrix.py` (set `THREEMF_UNIT_TABLE` to a file path to regenerate it).
Import reads a 20 mm cube at x = 100 mm from a file in each unit; export writes a 20 unit cube. "u" is Blender
units, as `dimensions` shows them, and "scale" is the imported object's scale. The test fails if any case loses
the real size, if a build item gets a scale, or if import scales an object when one unit is the file's unit.

| Scene units | Means | Import 20 mm cube from a mm file | from an inch file | from a metre file | Export 20 unit cube |
|---|---|---|---|---|---|
| None, scale 1 | 1 unit = 1 mm | 20 u, scale 1 | 20 u, scale 25.4 | 20 u, scale 1000 | 20 mm |
| None, scale 1, preference off | 1 unit = 1000 mm | 0.02 u, scale 0.001 | 0.02 u, scale 0.0254 | 0.02 u, scale 1 | 20000 mm |
| Metric, m, scale 1 (Blender's default) | 1 unit = 1000 mm | 0.02 u, scale 0.001 | 0.02 u, scale 0.0254 | 0.02 u, scale 1 | 20000 mm |
| Metric, mm, scale 1 | 1 unit = 1000 mm | 0.02 u, scale 0.001 | 0.02 u, scale 0.0254 | 0.02 u, scale 1 | 20000 mm |
| Metric, mm, scale 0.001 | 1 unit = 1 mm | 20 u, scale 1 | 20 u, scale 25.4 | 20 u, scale 1000 | 20 mm |
| Imperial, in, scale 1 | 1 unit = 1000 mm | 0.02 u, scale 0.001 | 0.02 u, scale 0.0254 | 0.02 u, scale 1 | 20000 mm |

Before 2.7.7-fork.16, and in upstream, Unit System None behaved like the "preference off" row.

## Notes

- **Unitless scenes.** With Unit System None, Blender has no unit. Unitless mesh formats (STL, OBJ, PLY) carry
  Blender's numbers as they are, and slicers and build preparation programs read them as millimetres, so 1 unit =
  1 mm is the common convention for 3D printing. This add-on reads unitless scenes that way too. The preference
  **Unitless Scenes in Millimeters** (Export and Import tabs, on by default) turns it off for 1 unit = 1 m.
- **Blender's default scene is Metric, metres, scale 1**, not unitless, so a millimetre file imports at a
  thousandth of a unit, with objects scaled 0.001. For millimetre work, set Unit System None, or Unit Scale 0.001.
- **Where scale goes.** On export the unit factor goes into the vertices, so build-item transforms are only
  rotation and translation. On import it goes on each object's scale. Exporting objects that an import scaled
  0.001 keeps the right size, but writes that 0.001 into every build item, with vertices ×1000.
- **Size readouts.** The export dialog shows the size in the file; the import dialog shows the size of the
  selected file (files whose model is up to 50 MB) and the scale its objects will get in this scene. Both flag a
  build under 1 mm or over 1 m, and import warns afterwards if what it brought in is.
